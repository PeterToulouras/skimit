Thirty commits skimit 0.2.2 said nothing about and thirty it said only how an effect changed, drawn
from the 575 of the replay by a fixed shuffle (sorted by the SHA-1 of the commit hash), each read
against its diff on GitHub on 2026-10-25. The question for a silent commit: did it change what a
way in does, or how, in a way a reviewer would want to know? For a commit with lines: is the line
true, and is it something a reviewer needed?

"Out of scope" is a change in a module the replay did not build. "Noise" is a line that is true of
the bytecode and tells a reviewer nothing: a helper swapped for a library's, a class renamed and
reworked. The verdict "wrong" marks a line that was not true; 0.2.3 addressed each of these, and
the last column shows what it says on the same commit.
